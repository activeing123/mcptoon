Six days ago I posted a Show HN for a CLI that sits between AI agents and MCP servers. 73 points, 49 comments. Half were technical corrections. They were right. Here's what I got wrong, and what the real numbers are. 1. My token counts were wrong. Original benchmark: 255 MCP tools = 90,804 tokens. Commenters said "verify with a real tokenizer." I did — tiktoken, cl100k_base, OpenAI's official BPE tokenizer. Real number: 39,964. Not 90,804. My figure was chars/4, not actual tokens. I conflated bytes with tokens. 90K sounds catastrophic; 40K is still bad but honest. 2. Unicode "optimizations" cost MORE tokens. I replaced true→T, false→F, null→∅, \n→↲. Fewer characters, right? Wrong. true is 1 token in cl100k_base. ∅ (U+2205) is 2 tokens. ↲ is 2 tokens. My optimization made things worse. Removed every Unicode substitution. Output now uses standard true/false/null — matching the official TOON spec (v4.1) which requires lowercase literals. 3. "Zero information lost" was false. --compact returns tool names only. I claimed "zero information lost." You lose descriptions, parameters, types. Fixed the README to describe each format by what it actually preserves. Real numbers (tiktoken cl100k_base, 255 tools, 5 servers): JSON full schemas: 39,964 tokens SLIM (name|param): 3,511 tokens (91% savings) Compact (names only): 581 tokens (98.5% savings) Reproduce: python _benchmark.py → assets/benchmark_data.json 91% is still significant. 40K → 3.5K for tool discovery. But 99.87% was indefensible. Stopped using it. What the tool does: MCP servers inject schemas into your context before any work starts. This CLI keeps them out. The agent runs shell commands to discover/call tools. Schemas live on disk, not in context. Only the compact result enters. Without proxy: 255 tools → 39,964 tokens in your context With proxy: 255 tools → 3,511 tokens (SLIM). 91% savings. 200KB Python CLI, zero dependencies. Works with Claude Code, Cursor, Codex — any agent that runs shell commands. What I learned: - Always verify token claims with a real tokenizer. chars/4 is a heuristic, not a measurement. - Read the spec before implementing. TOON v4.1 was clear: lowercase literals, no Unicode hacks. - Don't conflate "smaller" with "lossless." Compact is smaller because it drops info. That's a trade-off. - HN commenters made the project better. debazel caught the Unicode issue. saretup caught "zero info lost." philipp-gayret asked for real tokenizer data. stephantul pointed out I hadn't investigated tokenization. vunderba nailed it: "confuse token counts with byte counts." Current state: 167 stars, 429 tests, v0.5.0 on PyPI. TOON matches spec v4.1. Benchmark is tiktoken-verified and reproducible. Apache 2.0, zero deps. pip install mcptoon https://github.com/activeing123/mcptoon Thanks to everyone who commented. The criticism was sharper than the code, and the code is better for it.
